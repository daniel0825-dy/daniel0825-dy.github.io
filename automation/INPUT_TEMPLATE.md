# 원고 전달 양식

같은 블로그 저장소를 연결한 새 채팅에서 아래 양식과 자료를 보내면 된다. 전체 규칙을 매번 복사할 필요는 없지만, 첫 요청에 `AGENTS.md와 automation/ 문서 3개를 읽고 적용해줘`를 적으면 어떤 규칙을 확인해야 하는지 분명해진다. 저장소 접근이 없는 채팅에서는 규칙을 읽었다고 가정하지 않고 저장소 연결 또는 문서 전달부터 확인한다.

## 필수 입력

- MODE: `PUBLISH`, `EDIT`, `RESEARCH` 중 하나.
- TITLE: 사용자 제목. 의미 변경 없이 표현을 다듬을 필요가 있으면 변경안과 이유를 보고한다.
- 원고 또는 핵심 내용: 완성 원고, 메모, 첨부 원고 파일 또는 작성할 핵심 주장. 자료만 첨부한 경우 어느 파일을 원고로 사용할지 지정한다.

## 선택 입력 및 누락 처리

| 항목 | 입력 방법 | 생략할 때 |
|---|---|---|
| CATEGORY | 독후감 / 칼럼 / 마인드맵 중 하나 | 현재 저장소에 기본 분류가 없으므로 원고에 근거해 제안하고 확인. 확정 전 게시하지 않음 |
| TAGS | 기업분석 / 산업분석 / 기술분석 / 아이디어 중 필요한 값의 배열 | `[]`. 관련 태그를 제안할 수 있으나 사실을 생성하거나 임의로 분류 체계를 확대하지 않음 |
| PUBLICATION | REVIEW_REQUIRED / AUTO_PUBLISH | REVIEW_REQUIRED. RESEARCH도 기본은 승인 대기 |
| 참고자료 | URL, 기관·자료 제목, 발행일·기준일, 관련 문단 | 제공된 원고와 자료 범위에서 처리. 필요한 근거의 누락 표시 |
| 첨부파일 | 이미지·PDF·표·원고 파일과 각 파일의 용도 | 실제 자료가 없는데 파일·표·이미지를 있는 것처럼 생성하지 않음 |
| 작성 시점 | 원고 작성일 또는 데이터 기준 시점 | 모르면 표시. 게시일과 혼동하지 않음 |
| 추가 요구사항 | 원문 보존 수준, 소제목, 이미지 위치, 표 표시, 문체, 분량 | CONTENT_POLICY.md의 모드별 최소 변경 원칙과 기존 스타일 사용 |
| 게시 일시 | 필요할 때 한국 날짜·시간·시간대 지정 | 실행 시 확인한 한국 현재 시간. 미래 날짜이면 예약 배포 미구축 상태를 설명 |

`#칼럼`과 `#기업분석`은 독자가 검색할 때 사용하는 형식이다. 입력 양식과 Front Matter에는 `CATEGORY: 칼럼`, `TAGS: [기업분석]`처럼 실제 이름을 사용한다. 검색 별칭 `#컬럼` 때문에 분류를 `컬럼`으로 새로 만들지 않는다.

## 복사해서 사용하는 기본 양식

```text
AGENTS.md와 automation/의 문서 3개를 읽고 아래 원고를 처리해줘.

MODE: PUBLISH
TITLE: 여기에 제목
CATEGORY: 칼럼
TAGS: [산업분석, 기술분석]
PUBLICATION: REVIEW_REQUIRED

원고 또는 핵심 내용:
여기에 원고를 붙여넣거나 첨부 원고의 파일명을 적습니다.

참고자료:
- 자료 제목 / 기관 / 기준일 / URL / 관련 문단

첨부파일:
- figure-01.png: 첫 번째 소주제의 설명 직후 삽입
- comparison.xlsx: Sheet1 A1:F10을 비교 표로 사용
- source.pdf: 3~5쪽을 근거 확인용으로만 사용

작성 시점: 알고 있는 경우 기재
추가 요구사항: 주장을 유지하고 표·이미지를 관련 문단 뒤에 배치
```

파일명과 셀 범위는 예시다. 실제 파일을 첨부하고 실제 범위로 바꾼다. 선택 항목은 삭제해도 되며 필수 입력만 있어도 분석·초안을 시작할 수 있다. 누락된 분류나 중요한 정보는 게시 전에 확인한다.

## 모드와 게시 정책 예시

완성 원고를 먼저 확인:

```text
MODE: PUBLISH
TITLE: 완성 원고의 제목
PUBLICATION: REVIEW_REQUIRED
원고: 첨부 manuscript.md
```

문장·구조 편집 후 검증을 통과하면 게시:

```text
MODE: EDIT
TITLE: 산업 변화에 대한 생각
CATEGORY: 칼럼
TAGS: [산업분석, 아이디어]
PUBLICATION: AUTO_PUBLISH
원고: 아래 메모의 주장과 결론을 유지해 편집해줘.
```

자료조사 초안:

```text
MODE: RESEARCH
TITLE: 조사 주제
CATEGORY: 칼럼
원고 또는 핵심 내용: 핵심 질문과 검토할 주장
참고자료: 조사할 URL과 첨부 PDF
```

마지막 예시는 정책을 생략했으므로 REVIEW_REQUIRED다. 원고 작성일·표 단위·출처가 누락되면 그 사실을 보고하며, 이를 추측으로 채우지 않는다.

## 이미지·표·PDF 전달 안내

- 이미지: PNG/JPG/WebP/SVG 원본과 대체 설명·캡션·출처를 제공한다. 파일 순서 또는 삽입할 소주제를 지정하면 우선 적용한다. 원본 수정이 필요하면 원하는 변경도 적는다.
- 표: 가능하면 CSV/XLSX 또는 텍스트/Markdown 표로 전달한다. 열 제목·단위·기준일·출처를 함께 적는다. 스크린샷 표도 사용할 수 있지만 전사한 숫자를 원본과 대조하고 읽지 못한 셀을 보고한다.
- PDF: 원고 자체인지, 출처 확인용인지, 그림·표 추출용인지 지정한다. 관련 페이지를 알려주면 확인 범위를 분명히 할 수 있다. PDF 전체를 블로그에 복제하거나 첨부 원본을 자동 Push하지 않는다.
- URL: 링크가 어떤 주장이나 수치를 뒷받침하는지 알려준다. 접근할 수 없는 페이지는 검증 완료로 처리하지 않는다.

승인 대기 초안을 게시하려면 `이 초안과 첨부 이미지를 AUTO_PUBLISH로 게시해줘`처럼 대상을 명시한다. 상세 절차는 [PUBLISH_WORKFLOW.md](PUBLISH_WORKFLOW.md)를 따른다.
